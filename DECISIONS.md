# Deviations from CINEHOME-UI-SPEC.md

- **Playback provider is the scraper, not the stub.** The spec's section 21 says "do NOT implement any real provider" and ship only `StubPlaybackProvider`. Per explicit direction, `ScraperPlaybackProvider` (`src/lib/playback/scraper.ts`) wraps the existing Playwright scraper mini-service and is the default (`playback_provider` setting, changeable in Settings → Playback Provider). The stub is still implemented and selectable.
- **Single container, not two.** The app's `/api/playback` route calls the scraper at `http://localhost:3030` — that only works if both processes share a network namespace. Rather than split into `cinehome` + `scraper` containers (spec's compose snippet, which has this same bug), both run in one container via `start.sh`, matching how they were already deployed.
- **`movie-detail-view.tsx` / `tv-detail-view.tsx` merged into one `DetailView`** (`src/views/movie-detail.tsx`), parametrized by `mediaType`. The two pages are ~90% identical (rating, genres, cast, recommendations); the TV-only bits (seasons grid, last/next episode cards) are conditionally rendered. Avoids duplicating ~300 lines twice.
- **`src/types/tmdb.ts` not split out.** TMDB types live alongside the client in `src/lib/tmdb.ts` (as they did before this rewrite) instead of a separate types file — same information, one less file to keep in sync.
- **Trailer opens in a new tab, not a modal.** Spec says "opens YouTube modal"; linking out is simpler and avoids embedding YouTube's iframe (the player's own "no iframe" rule is about the *stream*, but embedding YouTube's player for trailers seemed like unnecessary scope for a secondary feature).
- **`watch/providers` fetched via `append_to_response` on the detail call**, not as a separate `tmdb.watchProviders()` round trip (the method exists for completeness but the page doesn't call it separately).
- **Season click navigates to `/tv/[id]/season/[n]`**, not straight to `/watch`, matching the spec's own route table (section 2) rather than the old app's shortcut.
- **Light theme added.** The original `globals.css` only had a dark palette (both `:root` and `.dark` were identical), so the spec's dark/light/system toggle was cosmetic. Added a real light palette so Settings → Appearance → Theme actually does something.
- **No `.ico` favicon.** `icon.svg` + `icon-192.png` are used instead; modern browsers don't need `.ico`, and generating one cleanly needs an extra dependency.
- **Accent color picker changes `--primary`/`--ring` inline via `style.setProperty`**, not a full design-token recompile — swapping the two variables that actually drive the crimson accent through the app is enough for a preference toggle without touching the Tailwind theme layer.
